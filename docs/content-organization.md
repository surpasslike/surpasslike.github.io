# 文章组织与写作

分类表达文章用途，专题组织阅读路线，标签用于跨专题查找具体技术。分类、专题和标签目录统一维护在 `source/_data/navigation.yml`。

## 新文章

1. 选择一个分类：**项目实践**记录实现与排查，**学习笔记**梳理概念与经验，**工具指南**说明安装和使用步骤。
2. 从标签目录中选择 **1–4 个**准确的标签；一个标签已能说明主题时，不必凑数。不再使用过于宽泛的 `Android` 标签。
3. 按需填写 `topic`：`calendar`、`automotive`、`compose` 或 `tooling`。专题和 `topic_order` 均可省略；无专题的文章仍会正常收录到分类和标签中。
4. 写清标题与摘要，保留准确的发布日期；`updated` 只在内容实质更新时调整。

```yaml
categories:
  - 学习笔记
tags:
  - Kotlin
  - 协程
topic: calendar
```

专题页会按文章元数据自动收录，无需手工添加文章链接。示例不指定顺序，会排在该专题已有编号的文章之后，再按发布日期和文章路径排序。需要指定阅读顺序时，再填写正整数 `topic_order`；此时必须同时填写 `topic`，且序号不能与同专题文章重复。草稿发布前须补齐分类和标签，专题与顺序按需填写。

## 专题与系列

`topic` 是专题归属；`series` 仅用于有连续阅读关系的文章侧栏，不作为第二套专题目录。目前仅 Calendar 的需求、架构、提醒三篇保留 `series: Calendar日历应用`，侧栏按发布时间从早到晚展示。不要为单篇文章新建系列。

新增专题或标签时，先判断是否已有合适条目，再更新目录和文章元数据。专题 `id` 也用于页面锚点，应保持稳定。

## 预览与生成

每轮生成都会根据当前发布文章重建导航。页面渲染只合并数据副本，不回写文章正文或已有侧栏组件。片段缓存按生成轮次隔离，避免预览更新期间的旧页面请求把旧计数带入新页面；调整生成流程或升级依赖后，应验证同一预览进程中的新增、修改和删除都能刷新导航。

## 链接与发布检查

文章文件名和永久链接保持稳定。分类或标签重命名、合并时，在 `source/_data/redirects.yml` 逐条补充旧路径到有效目标的映射；目标可带专题锚点，避免跳转链或循环。兼容页使用页面跳转，不是 HTTP 301。

发布前完成构建和内容检查，确认文章归属、阅读顺序、标签计数、旧链接跳转正常；同时检查分类、专题和标签页在电脑与手机上的显示。
